# Resolve handoff

To *prove* a handoff in Resolve (import, edit, export, compare), use [resolve-acceptance.md](resolve-acceptance.md).

The primary export is OpenTimelineIO, a format Resolve supports for timeline import and export. This implementation uses OTIO objects and its serializer, with an XML fallback written by the community FCP adapter.

## Unit 9 package

- 57 separate picture clips in `production/shots/`.
- Editorial body: 7,194 frames at 30 fps, or 239.8 seconds.
- Each clip has 12 extra frames on each side, so its OTIO source in-point is frame 12.
- The original 48 kHz stereo WAV is a single audio clip at time zero.
- Chosen action and speech cues are on the video track. Machine audio-onset candidates are on the audio track.
- The main MP4 is a viewing reference. Its AAC audio does not replace the original WAV in the edit.

## Import and edit

1. Choose **File → Import → Timeline** and select `unit-9-human-edit.otio`.
2. Allow the referenced source clips to load. If media moved, regenerate the OTIO or relink the shot folder and original WAV.
3. Confirm 1920 × 1080 and 30 fps, and compare the first cut and ending to the viewing reference.
4. Lock the original audio track. Then trim, slip, move, or hold picture clips to shape the performance.
5. Preserve your human edit as a new Resolve timeline. Export an OTIO copy alongside your Resolve project when you want a portable editorial record.

Twelve-frame handles give 0.4 seconds of adjustment at each edge. They are generated by the same shot's SVG function: normalized action progress holds at the boundary, while applicable clock-based details can continue. They are not invented coverage. Extend a source shot in its scene code if more action or a different pose is needed.

## Limits and acceptance

The local checks establish frame ranges, file existence, media hashes, and a successful OTIO serialization round trip. They do not establish native Resolve import, marker appearance, track locking, project color-management settings, or device playback. Resolve was not detected in the standard application locations on this host.

No Resolve database or `.drp` file is fabricated. Native project creation through the scripting SDK can be added after the installed edition and SDK are inspected. OTIO is sufficient to generate the initial editable timeline without controlling the application.

The SVG scene graph is not converted into Fusion. Individual shot clips contain baked artwork and motion. Resolve controls editorial timing, compositing of those clips, and grading; source SVG/code controls the animation within a clip.

## Collected media and human returns

New schema-2 builds can use `package` to collect relative-reference OTIO, handled
clips, the original recording, and editorial context into a fresh folder.
`package-check` works after moving that folder, without the original film.
`compare-return` reads an editor OTIO export against the saved package, reports
timing and media changes, and never applies edits. See the
[portable editorial workflow](portable-editorial.md) for short commands, native
Motion Canvas shot registration, and comparison coverage. The preserved Unit 9
legacy outputs require a deliberate rebuild before entering this packaging path.
